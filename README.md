# 🗳️ CampusVote — Blockchain-Based College Election System

An **educational** decentralized application (dApp) that runs a college student-council election on an Ethereum-compatible blockchain.

- **Smart contract:** Solidity `0.8.28` (`contracts/VotingSystem.sol`)
- **Dev chain and tests:** Hardhat 2 (mocha + chai + ethers)
- **Frontend:** React 19 + Vite + Tailwind CSS v4
- **Wallet / chain access:** MetaMask + ethers.js v6

> ⚠️ **Educational demo only.** Do not use this for legally binding elections. Votes on a blockchain are *pseudonymous, not secret*: anyone can see which wallet voted for which candidate. A wallet address is also not a verified human identity.

---

## Features

| Area | What it does |
|---|---|
| Landing page | Hero, live election snapshot (status, votes, turnout, current leader), how-it-works, features |
| Vote dashboard | Election status, stats, your voter status, candidate cards (name, party, symbol, manifesto, votes), confirm-before-vote dialog |
| Results | Live leader/winner banner, ranked bar chart with vote counts and percentages, turnout. Auto-refreshes every 5 s |
| Admin (owner only) | Add candidates, register/remove voters (batch paste), start/end the election with confirmation, voter lookup |
| Wallet | Connect/disconnect MetaMask, shows the address (click to copy), admin badge, detects the wrong network and offers a one-click switch/add of the Hardhat network |
| Transactions | Progress panel: contract check → confirm in MetaMask → pending → confirmed (tx hash and block). Success/error toasts with human-readable contract errors. Data refreshes after confirmation |
| Read-only mode | Without MetaMask the site still reads candidates and results directly from the node |

### Smart-contract rules

- Lifecycle is one-way: **Setup → Active → Ended** (no restarts).
- Only the **owner** can add candidates, register/remove voters, start/end the election, and transfer ownership.
- Candidates can only be added during Setup. Starting the election requires at least one candidate.
- Voters must be registered (eligible). Registration is allowed during Setup and Active, and removal only during Setup.
- Each eligible wallet can vote **exactly once**. Votes for non-existent candidates and votes outside the Active phase are rejected.
- Vote counts, candidates, status, voter status and leaders are public `view` functions.
- Validation uses **custom errors** (`NotOwner`, `InvalidState`, `NotEligible`, `AlreadyVoted`, `InvalidCandidate`, …). Input lengths are bounded, loops are bounded (max 50 candidates, max 200 voters per batch), and there are no external calls (no reentrancy surface).

## 1. Prerequisites

- **Node.js 20.19+ or 22+** (tested with Node 24) and npm
- **Google Chrome / Brave / Firefox** with the **[MetaMask](https://metamask.io/download/)** extension
- (Optional) VS Code with the Solidity extension

## 2. Installation

```bash
npm install
```
Installs React, Vite, Tailwind, ethers.js, and Hardhat with its toolbox.

(Optional) `cp .env.example .env` lets you change the defaults. **No env vars are required for local use.**

---

## 3. Compile and test the smart contract

```bash
npm run compile     # = npx hardhat compile → writes artifacts/
npm test            # = npx hardhat test    → runs 26 tests on an in-memory chain
npm run coverage    # (optional) solidity-coverage report
```

The tests cover deployment, candidate registration and validation, voter registration, lifecycle rules, voting (double voting, ineligible voters, invalid candidates, voting before start and after end), results/ties, and ownership.

---

## 4. Start the local blockchain

Open **terminal #1** and leave it running:

```bash
npm run chain       # = npx hardhat node
```

This starts a JSON-RPC node at `http://127.0.0.1:8545` (chain ID **31337**) and prints 20 test accounts, each with 10,000 test ETH and a private key.

> 🔐 These keys are **public, well-known test keys**. Never send real funds to them or use them on a real network.

## 5. Deploy the contract locally

Open **terminal #2**:

```bash
npm run deploy:local   # = npx hardhat run scripts/deploy.cjs --network localhost
```

The script:
1. Deploys `VotingSystem` from **Account #0**, which becomes the **admin/owner**.
2. Seeds demo data: 4 candidates, with **Accounts #1–#5** registered as eligible voters. Set `SEED_DEMO=false` in `.env` to start empty.
3. Writes **`src/contracts/VotingSystem.json`** with the contract `address`, `chainId` and `abi`.

The script refuses to deploy to any non-local chain. Nothing is ever deployed to a public blockchain.

## 6. Configure the frontend (address and ABI)

**This is automatic.** The frontend imports `src/contracts/VotingSystem.json` created in step 5. Each redeploy updates the file, and Vite reloads the page.

Manual overrides (optional, in `.env`, then restart `npm run dev`):

| Variable | Default | Purpose |
|---|---|---|
| `VITE_CONTRACT_ADDRESS` | from JSON | Use a different deployed address (ABI still comes from the JSON) |
| `VITE_RPC_URL` | `http://127.0.0.1:8545` | Node used for read-only calls |
| `VITE_CHAIN_ID` | `31337` | Chain MetaMask must be on |

Only `VITE_`-prefixed variables reach the browser, so **never put private keys in them**. The frontend never handles private keys: all signing happens inside MetaMask.

## 7. Run the website

**Terminal #3:**

```bash
npm run dev          # http://localhost:5173
```

Production build: `npm run build`, then `npm run preview`.

---

## 8. Connect MetaMask to the local chain

1. **Add the network.** Click **Connect MetaMask** on the site. If the site shows *"Switch network"*, click it and MetaMask offers to add/switch to **Hardhat Localhost**. To add it manually instead (MetaMask → Networks → Add network manually):
   - Network name: `Hardhat Localhost`
   - RPC URL: `http://127.0.0.1:8545`
   - Chain ID: `31337`
   - Currency symbol: `ETH`
2. **Import test accounts.** In MetaMask, go to Account menu → *Add account or hardware wallet* → *Import account*, and paste a private key that `npm run chain` printed in terminal #1:
   - **Account #0** → the election **admin**
   - **Accounts #1–#5** → eligible **voters** (when seeded)
   - Account #6 or higher → an **unregistered** wallet (useful for testing rejection)
3. Pick the account in MetaMask and click **Connect MetaMask** on the site. Your address appears in the navbar (with an **ADMIN** badge for Account #0).

---

## 9. Test the complete voting workflow

1. **As admin (Account #0)**, open the **Admin** page:
   - (Optional) add another candidate with the form, which opens a MetaMask transaction.
   - (Optional) register more voter addresses (paste one per line).
   - Click **Start election** → *Yes, open voting* → confirm in MetaMask. The status changes to **Voting open**.
2. **As a voter (Account #1)**, switch accounts in MetaMask (the site updates automatically) and open **Vote**:
   - The status card says *"You're eligible to vote"*.
   - Click **Vote for …** on a candidate → **Confirm vote** → confirm in MetaMask.
   - Watch the progress panel: *Checking → Confirm in MetaMask → Waiting for block → Confirmed*.
   - Counts update and the card says *"Vote recorded ✓"*.
3. **Try to break it:**
   - Vote again with Account #1 → buttons are disabled (*"You have already voted"*). The contract also rejects it with `AlreadyVoted`.
   - Use Account #6 (unregistered) → *"Not an eligible voter"*.
   - Try admin actions from a voter account → the Admin page is read-only, and the contract rejects them with `NotOwner`.
4. Vote with Accounts #2–#5 and watch **Results** update live (counts, percentages, turnout, leader 👑).
5. **As admin**, click **End election**. Voting closes and Results shows the **🏆 Winner** (or a tie).

## Troubleshooting

| Problem | Fix |
|---|---|
| *"Contract not deployed yet"* page | Run `npm run deploy:local` (with `npm run chain` running). |
| *"No contract found at 0x…"* | The Hardhat node was restarted (its state resets). Run `npm run deploy:local` again. |
| *"Cannot reach the blockchain node"* | Start `npm run chain` in another terminal. |
| *Nonce too high* / stuck transactions after restarting the node | MetaMask → Settings → Advanced → **Clear activity tab data**, then retry. |
| Wrong-network banner | Click **Switch network** or select *Hardhat Localhost* in MetaMask. |
| *"MetaMask not found"* | Install the extension and reload. The site still works read-only. |

## Security notes and limitations

- Private keys never appear in the frontend. `.env` is git-ignored, and `hardhat.config.cjs` has **no public networks configured**. Add one only if you deliberately choose to deploy publicly.
- On-chain votes are **public and linkable to wallets**, so there is no ballot secrecy.
- Voter eligibility is managed by a single admin key, which is a centralization and trust point.
- The admin controls start and end times manually (no automatic deadlines).
- The contract has not been professionally audited.
